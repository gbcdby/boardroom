# whole-brd F2：私有目标准备与普通元数据采集

本入口实现 [#152 接受的 F2 范围](https://github.com/gbcdby/boardroom/issues/152#issuecomment-6892780062)：同一次启动的普通 P1 输入先通过，管理者准备一个 64 MiB whole-brd，普通身份读取固定元数据，最后回收所有本次拥有的资源。它沿用 [source-preservation r2](https://github.com/gbcdby/boardroom/issues/152#issuecomment-6881600918)。

成功状态最多是 `F2_METADATA_CAPTURED`，资格保持 `UNSUPPORTED`，内容探针数量固定为 0。它不注册 provider，不创建生产 DB/source/plan 绑定，也不释放完整 F1、Fs/M04、R05 或 #152 的整体验收。普通健康零值只表示当次可见快照，不承诺诊断最终提交。

## 入口和固定边界

| 文件 | 职责 |
| --- | --- |
| `f2.py` | 固定方案、格式化参数、42 成员归档白名单和分源原件消费者 |
| `f2-build.py` | 校验已有输入，有限编译静态 helper，生成独立离线 bundle |
| `f2-guest.c` | guest 内的普通输入门、唯一管理创建者、普通元数据 actor 和失败回收 |
| `f2-run.py` | 验证 bundle/source，创建单次 claim，复用自有子进程与管道实现并保存结果 |
| `mke2fs-f2.conf` | 精确受控配置，不接受等价配置或宿主默认回退 |
| `tests/whole-brd-f2.test.py` | 纯输入、合成 ABI、错误保留与虚拟系统调用控制 |

原 F0/F0B 的零目标归档、旧 bundle、run ID 和 claim 保持独立。新 F2 归档只允许固定目录、console/null 字符节点、BusyBox、新 helper、配置、模块、notes、三项 UUID 内容及固定的 8 个 e2fs ELF / 8 个相对链接。没有预建 block node、磁盘共享、网络或任意命令入口。

## 准备和运行是两个阶段

离线准备的 JSON 仅允许 `run_id`、`base_bundle`、`base_bundle_sha256`、`brd`、`payload_root`。所有路径必须是明确的绝对输入路径。基础 bundle 提供已核定的 kernel、QEMU、BIOS、BusyBox、notes、host gate 以及库和 firmware 清单；新模块、配置和 e2fs 文件再按固定大小、内容摘要和链接目标核对。编译只针对新 F2 helper，10 秒上限；离线准备 60 秒上限。准备过程不执行 helper、mke2fs、module 或 guest。

`f2-build.py --request REQUEST --output NEW_BUNDLE_DIRECTORY` 只接受新的独占目录，结果为 `FIXED_F2_BUNDLE_NOT_BOOTED` 或保留原错误的 `OFFLINE_BUILD_FAILED`。文件系统 UUID 与目录 hash seed 由新 run ID 的固定规则导出并写入归档及 bundle，运行时不能覆盖。16 个实际导入或编译的源码输入均记录路径、大小与 SHA-256；执行时必须逐项一致。

一次实际运行还需要精确 source、BUNDLE SHA、run ID、输入闭包、固定 argv、资源、输出和 executor 的独立两轴核对与总控明确释放。标准 CI 不调用运行入口。释放后的 `f2-run.py --bundle BUNDLE --bundle-sha256 SHA --output NEW_OUTPUT_DIRECTORY` 只在该 BUNDLE 所在目录独占创建一次 `EXECUTION-ATTEMPT.json`；存在 claim 即拒绝。不能删除 claim、换 ID 或修改参数规避失败。

调用方必须独立保存入口 stdout、stderr 和退出码。`RESULT.json` 写在工件最终关闭之前；最终关闭结果由 stdout 中的 `final_artifact_errors` 提供，不能只读 RESULT 就判断通过。任何 metadata/close 失败单独保留，首个执行错误不被覆盖。输出目录、claim 和原件保留作结果审查，不自动清理失败现场。

## guest 内严格次序

1. 第一个普通 child 由管理 parent 创建，在 ACK 前取得 pidfd；child 降为 UID/GID 1000、空 groups、五 capability 集合全零、NNP=1。它读取 19 个原件，包括前后身份、完整 uname/notes/cmdline、modules、brd presence 和实际 block 列表。
2. 程序在目标创建前匹配精确 vendor build、notes、完整固定 cmdline 和未加载 brd 的现状；原 child 成功退出并 reap 后才能继续。原始 loop 对象允许存在并如实保留；不访问或接管它们。该门复用[已接受的 P1 源码解释](https://github.com/gbcdby/boardroom/issues/152#issuecomment-6892768329)，不是 direct getter，也不能复用旧 boot 的普通身份。
3. 管理者核配置实际字节及对象身份，加载固定 brd 模块并核 family，只创建自己的 `/dev/ram0`。目标容量必须为 64 MiB，实际 logical block size 不超过 1024；physical size 另存，不代填 logical size。
4. 唯一格式化 child 使用固定 ELF、argv、环境，ACK 前取得 pidfd，stdin 为自有 `/dev/null`，stdout/stderr 各 64 KiB，30 秒期限。任何未知 ABI、配置、helper 或格式化错误均停止，不下载、不调整 flags、不再试。真实退出、reap 和两路 EOF 后才继续。
5. 对已卸载目标保存有限 raw superblock、group descriptor、journal inode 和 journal header；关闭管理 FD 后 fresh mount native ext4。请求 `rw,data=ordered,dax=never,errors=remount-ro,acl,user_xattr`，mount flags 为 nosuid/nodev/noexec/relatime。根 inode 2 设为 UID/GID 1000、0700，不创建应用内容。
6. 第二个普通 child 仅读取固定 source 根 FD 和允许的 proc/sysfs 元数据：same-FD stat/statfs、UUID/FID、legacy/unique mount ID、statmount、GET_TUNE、flags、有效配置、可见健康字段，以及 module/build/geometry/whole-device 库存。47 项普通帧与管理帧分开保存，前后身份和 source FD 对象必须一致。
7. parent 收到真实普通退出并回收后，逐个关闭拥有的 FD，对同身份目标 unmount、读取已卸载有限元数据、移除自有 node、卸载自有 module，输出完整收尾记录。一个关闭失败不能跳过其他回收；不触碰未知资源。最后结束实例，由 host 自有 QMP、pipe、pidfd、wait/reap 和工件封存完成收束。

消费者同时验证两种帧在同一串口中的次序：P1 普通原件必须落在其拥有阶段内并先于目标准备，不能事后补入。管理 receipt 不能代替普通获取，缺失、重复、乱序、错误、未知字段或收尾不完整不能成为 `F2_METADATA_CAPTURED`。

`guest-complete` 仅声明 guest 资源收束，不等于已观察 poweroff。host 在原总预算内额外等待至多 5 秒，记录 QEMU 实际退出；只有未发送 host quit 前退出 0，且最终收尾没有 forced、wait timeout、未 reap 或关闭错误，才允许成功状态。逾期才进入既有 QMP/信号回收并保留原超时，强制结束不能改写为成功。

## 格式与结果边界

受控配置 SHA-256 为 `29ff35ee2a05a0c672271c378be8626e71f2ab71c3e553af8dd91196a40d7e23`。显式 `-T brd64 -b 4096 -I 256 -i 16384` 排除 small profile 默认块大小；`-O none,...` 先清除默认特性再设置已接受的 14 项；单个 `-E` 固定 eager inode/journal 初始化、nodiscard 和 `assume_storage_prezeroed=0`，配置本身也禁用 lazy/discard/undo。

| 实际字段 | 接受值 |
| --- | --- |
| 容量、块大小、inode 大小 | 16,384 × 4096 字节；inode 256 字节 |
| ext4 feature masks | 卸载 `60 / 706 / 1131`；挂载 `60 / 710 / 1131` |
| journal | 内部 inode 8，4 MiB；实际大小、UUID、header 和特性另读核对 |
| host / guest 预算 | guest 512 MiB、1 vCPU；host child AS 2 GiB、CPU 300 秒、core 0 |
| 时间 | boot / stage 60 秒；每个 ordinary 3 秒；fixture 300 秒；外层 job 600 秒 |
| 输出 | initramfs 压缩 16 MiB / 展开 32 MiB；serial 8 MiB；工件总量 64 MiB |

raw journal header 用来确认有限几何与已支持格式，不是完整事务分类或内容保全证明。完整生产 source/DB/plan 绑定、M04 writer 和特殊路径覆盖、来源保全与 R05 均在结果 `unresolved` 中保留。运行失败只记录 `FAILED_NO_RETRY` 或 `EVIDENCE_UNPROVEN`，不会扩大资格。

## 本地及 CI 纯控制

```text
python3 -B tests/whole-brd-f2.test.py
```

测试使用明确的合成原件来验证解析，不把合成 UUID、inode、journal 或 health 数据计作资格证据。C 收尾控制编译一个替换目标系统调用的测试翻译单元；测试子程序只使用虚拟 FD、fork、pidfd 和输出，实际 guest/helper payload、格式化、设备及模块调用均不执行。真实 F2 包及实际一次运行的验收结果分别记录在 #152，不由这些纯控制推断。
