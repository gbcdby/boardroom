# 项目记忆维护

## 目的

`CONTEXT.md` 是项目内跨 agent、跨会话共享的记忆，用来保存**非显而易见、可复用、且无法从代码或正式文档直接得到**的事实。本技能规定何时读、何时写、如何维护；它不替代正式需求文档、任务系统或临时输出目录。

## 项目适配

本技能默认使用下列约定。宿主项目已有自己的规范时，以宿主项目为准，不要照搬默认路径。

| 用途 | 默认约定 | 说明 |
| --- | --- | --- |
| 记忆文件 | 仓库根目录 `CONTEXT.md` | 可放在项目根目录；不要放进临时目录 |
| agent 约定 | `AGENTS.md`、`CLAUDE.md` 或等价文件 | 先读其中的目录、流程与边界约定 |
| 正式需求/设计 | issue tracker 或项目管理工具 | 产品需求、范围、验收标准与稳定决策的归属 |
| 任务跟踪 | issue tracker 或项目管理工具 | decision map、spec、ticket 状态与进度的归属 |
| 临时输出 | `.agent-output/` 或项目约定目录 | 日志、草稿、调研记录的归属 |
| 技能目录 | `.agents/skills/`、`.claude/skills/` 或用户级技能目录 | 可重复流程的升级目标 |

## 初始化

如果项目根目录还没有 `CONTEXT.md`，首次使用时按下面的最小骨架创建；不要预填猜测内容：

```markdown
# CONTEXT.md — 项目独有记忆

> 保存非显而易见、跨会话仍有效的项目知识。维护规则见项目技能 `project-memory`。
> 不记录：需求、范围、验收标准、任务状态、过程日志，或可从代码/文档直接得到的信息。
> 条目注明日期、适用范围和证据；未复现的推测写入「待验证」，不得写成已确认事实。

| --- | --- | --- |

| 环境 / 宿主 | 版本 | 能力或差异 | 测试条件与结果 | 日期 |
```

## 读取

开始非平凡任务前：

1. 阅读项目的 agent 约定文件（如 `AGENTS.md` / `CLAUDE.md`），再查看 `CONTEXT.md` 中与当前任务相关的章节。
2. 用关键词检索（`rg` 或等价工具），不必默认通读全文。`CONTEXT.md` 只提供线索，关键结论仍要回到代码、正式文档或实测证据确认。
3. 发现 `CONTEXT.md` 与正式文档、代码或实测结果冲突时：
   - 「应然」以正式需求/设计文档为准，「实然」以可复现证据为准；
   - 在 `CONTEXT.md` 中标记冲突并写清证据，不要静默删改；
   - 必要时请用户裁决。

## 何时写入

满足以下任一条件才写入：

- 某个术语在本项目中有特殊含义，且容易与通用含义或其他实体混淆。
- 实际复现了一个非显而易见的坑（宿主行为、协议边界、库的边界、环境差异）。
- 发现了一条反直觉、但会影响后续实现的约束。
- 有一个值得后续验证的技术假设，且会影响实现选择。

不写入：

- 需求、范围、验收标准 → 正式需求/设计文档。
- 任务状态、负责人、进度 → 任务系统。
- 一次性的调试过程、命令输出、聊天记录 → 临时输出目录。
- 从代码结构、类型定义或 git 历史可直接看出的信息。
- 通用编程知识，或官方文档中稳定且易于查阅的内容。
- 密钥、令牌、个人信息。

## 怎么写

1. **先搜后写**：用关键词搜索已有条目；能更新就不新增，能合并就不另起一节。
2. **一条一个事实**：条目保持原子化，避免把多个结论塞进一段。
3. **必须有证据**：写明日期、适用范围和验证方式（文件、命令、commit、链接）。未复现的推断只能进「待验证」。
4. **按章节格式写**：
   - 术语：术语、在本项目中的含义、来源。
   - 环境/宿主差异：环境或宿主、版本、能力/差异、测试条件与结果、日期。
   - 踩坑：现象、原因、结论/做法、适用范围、证据。
   - 待验证：假设/问题、影响、验证方法、状态。
5. **区分应然与实然**：正式文档写的是目标行为，代码和实测反映的是当前行为；不要用其一覆盖另一。
6. **并发安全**：修改前重新读取相关章节；只做局部编辑，不重排无关内容；不静默改写其他 agent 的条目，修正时追加日期和理由。

## 维护与淘汰

- 软上限约 150 行；接近上限时先合并重复、删除已失效条目，而不是继续堆叠。项目规模较大时可调整上限，但要保持文件可读。
- 以下内容应迁出：
  - 稳定下来的需求或决策 → 正式需求/设计文档；
  - 可重复执行的操作流程 → 项目的技能目录；
  - 任务状态与工作项 → 任务系统；
  - 一次性材料 → 临时输出目录。
- 过时条目标注「已过时」、日期和替代来源，再删除；不要留下无来源的历史残片。
- 每次任务结束前，若本次产生了符合收录标准的事实，做一次增量更新；没有就不写，不要为更新而更新。

## 与其他文档的关系

- agent 约定文件：始终加载的工作约定；`CONTEXT.md` 不重复其中的规则。
- 正式需求/设计文档：需求与验收标准的唯一来源；`CONTEXT.md` 只记录实现过程中补充的事实。
- 任务系统：工作项与状态；不要把任务进度写进 `CONTEXT.md`。
- 临时输出目录：过程材料；需要长期保留的结论才提炼进 `CONTEXT.md` 或正式文档。

## 复用

本技能不依赖特定项目路径。复制本目录（至少 `SKILL.md`）到目标项目的 `.claude/skills/project-memory/` 或用户级技能目录即可；目标项目没有 `CONTEXT.md` 时，按「初始化」创建。

## 反模式

- 把聊天记录、日志或大段命令输出直接贴进 `CONTEXT.md`。
- 把推测写成事实，或不注明日期与适用范围。
- 同一条坑重复记录多次，或为每条小发现都新增一节。
- 让文件无限增长，最后没人愿意读。
- 静默覆盖其他 agent 的条目。
- 把正式文档已明确的需求再抄一遍。
- 把某个项目的专有路径、术语或团队约定硬编码进本技能。
