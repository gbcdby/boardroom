# 事实调查

## 目标

回答一个问题，给出可追溯的事实。调查把决策留给用户或 `interview`，自己只负责把事实查清、记全、标好来源。

## 适用场景

- 解决 `decision-map` 中的 research 票。
- 核对官方文档、源码、规范、第一方 API 的实际行为。
- 核对宿主能力（Claude Code、Codex CLI 等）的版本差异和限制。
- 把阅读、检索和交叉核对交给后台 agent，主流程继续推进。

## 前置条件

- 问题明确且可回答；太宽时先拆成多张票或子问题。
- 明确需要哪些事实、什么结果算「调查完成」。
- 知道结果写到哪里：决策票、项目约定的调查目录，或临时输出目录。

## 流程

1. **重述问题与边界**：要回答什么、不回答什么、哪些属于后续决策。
2. **优先一手来源**：官方文档、源码、规范、第一方 API、实际运行输出。二手文章只作为线索，必须回到它引用的原始来源。
3. **记录每条关键事实**：来源、版本/日期、引用或链接、获取方式。能运行验证的就运行；把文档声明和实测行为分开写。
4. **交叉核对**：来源冲突时都列出，说明差异和可能原因；无法确认的标为未知。
5. **输出结果**：使用下面的模板，结论在前，证据在后。
6. **写回**：决策票用评论或链接；独立调查写到项目约定位置（默认 `.agent-output/research/<slug>.md`；需要长期保留时按项目文档规则升级）。
7. **停止**：只报告事实和影响；需要拍板时交给 `interview` 或用户。

## 输出模板

```markdown
## 问题

<一句话重述>

## 结论

<简短回答；没有确定答案时写「未能确认」并说明卡点>

## 证据

| 主张 | 来源 | 版本 / 日期 | 获取或验证方式 |
| --- | --- | --- | --- |
| ... | <官方文档/源码/命令> | ... | ... |

## 冲突与未知

<来源冲突、未覆盖的情况、需要实测才能确认的项>

## 对决策的影响

<事实层面；明确区分事实、推断和建议>

## 复现环境

<命令、宿主版本、依赖版本、日期>
```

## 规则

- 一手来源优先；每个关键主张都能追到拥有它的来源。
- 记录版本、日期、命令和环境；宿主能力必须实测，或明确标注「未实测」。
- 区分事实、推断和建议；建议必须显式标注。
- 不修改代码、spec 或 ticket 的决策；只写调查记录。
- 时间盒：问题太宽时拆成多张 research 票，不无限展开。
- 宿主支持后台子 agent 时，可把调查放到后台执行；结果仍按同一模板落盘。
- 引用日志或配置时脱敏，不记录密钥和敏感正文。

## 反模式

- 用二手博客或转述代替官方来源。
- 把文档声明写成实测结论。
- 只给结论，不给来源、版本或复现方式。
- 在调查中顺手改代码、改 spec 或替用户做决策。
- 没有边界地开放式研究，迟迟不收敛。
- 忽略来源冲突，只挑支持自己结论的证据。

## 与其他技能的关系

- `decision-map`：解决其中的 research 票，结果写回票并更新地图。
- `interview` / `to-spec`：为决策和需求提供事实输入；调查本身不产出需求。
- `prototype`：需要写一次性代码或跑通原型才能回答时使用；纯查证用本技能。
