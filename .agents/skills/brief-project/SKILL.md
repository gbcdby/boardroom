# 项目图景与决策

让人先看懂变化和需要判断的事情，再按需深入证据。以当前权威记录为依据，不把摘要变成另一套项目事实。

## 只读边界

- 允许读取项目记录、源码、已有模型和图、运行证据、PR 与目标环境的只读状态。
- 不领取任务、不确认消息、不修改授权、不接受架构基线、不执行合并、部署、模型检查或应用验证。
- 可以输出用户请求的简报文件或阅读视图；不得因此回写工作状态、把任务标为完成或把“已看过”标为“已接受”。
- 若需要新的运行证据或更新模型，列出精确缺口并交回相应工作。不要为制作简报调用带执行副作用的生成流程。
- 不依赖 boardroom 或特定宿主。房间只有带副作用的加入接口可用于取数时，使用已有可读资料并说明缺口，不擅自入群。

## 按需资料

| 当前需要 | 读取 |
| --- | --- |
| 汇总状态、累计变化和决策，或发现互相冲突的数据 | [简报视图规则](references/views.md) |

## 1. 确定用户想掌握的范围

1. 明确是一个工作项、一个子系统、整个项目，还是明确指定的一组项目。不要为了“全面”读取无关项目。
2. 识别用户此刻的问题：发生了什么、现在怎样工作、为何改变、还缺什么，或哪里需要决定。
3. 找到项目既有的权威工作单、架构基线、代码和证据记录。不存在的记录直接标明，不从最近聊天补造批准或部署事实。
4. 记录本次观察时间、所读对象的版本和资料时效；把旧报告与新事实分开。
5. 必要时做有界只读核对。摘要与原始材料矛盾时优先查明来源，不通过多数摘要投票解决。

## 2. 按实际目标报告状态

分别表达目标终点与当前事实，避免一个笼统的“完成百分比”。

| 已观察事实 | 不可推导的结论 |
| --- | --- |
| 设计或模型产物存在 | 代码已实现或已验证 |
| 某个候选检查通过 | 修改后的候选仍通过 |
| PR ready 或自动合并已设置 | PR 实际进入了目标分支 |
| 代码已合并 | 已发布、已部署或已经验收 |
| 部署请求已受理 | 目标环境确实运行指定版本 |
| 一次验收通过 | 无限期无故障 |

为关键结论提供可以打开或读取的证据。证据本身缺少对象、环境或范围时，显示为受限或未知，不自行补齐。

## 3. 组织三种阅读视图

### 行为视图

说明用户或调用者在关键情境下会经历什么，突出本次修改的路径、异常和尚未明确的语义。读取已有有效图；无图时可从已核对事实制作带版本与限制的阅读图，不借此创造新的产品承诺。

### 架构视图

展示相关模块职责、数据与状态归属、关键接口和依赖。区分拟议、已实现、已合并、已部署和已验证状态，不把计划节点画成已经运行的系统。

同时比较相对上次观察的变化，以及相对已接受基线的累计变化。若基线不存在或过期，写明无法评估累计偏移；不要自动把当前架构变成新基线。

### 变更与证据视图

说明本次实际成果、影响范围、通过或失败的检查、未覆盖部分以及证据失效原因。模型结果、源码对应与真实运行结果分开展示，不用一个绿灯代表全部层次。

## 4. 把人的注意力放到决定上

- 默认优先展示实际成果、重要架构或行为变化、交付阻塞和确需人的决定。
- 每个决定给出问题、已有事实、推荐项、替代项、代价、影响的工作与等待后果。
- 将同一前提和权限范围内的重复决定合并；前提变化、作用范围不同或后果不同的决定保留区别。
- 已有有效决定直接引用。人的沉默不新增授权，阅读简报不接受新基线。
- 保留影响当前交付的未解决分歧，说明证据差异；不要通过压缩摘要抹去少数但有依据的反例。
- 资料很多时先给短摘要、总量和展开入口。重要阻塞不能因显示数量限制而静默消失。

## 5. 需要时增加房间视角

只使用当前房间真正提供的读取能力，展示与用户问题有关的任务、角色、协作事件和证据。

- 区分全局身份、项目成员、连接状态、工作状态和任务完成状态。
- 不把成员在线、正在等待或聊天活跃解释为工作已经推进。
- 展示反复交接、无新增证据的讨论和影响交付的等待；没有测量依据时不根据消息数量评价贡献。
- 跨任务共享决定按适用范围去重；原始讨论保留可追溯入口，不要求用户逐个阅读每位 Agent 的日志。

## 6. 输出并结束

使用 [简报模板](assets/brief.template.md) 的必要部分。默认先写结论与最需要看的变化，再提供详细证据；不要回放完整执行时间线。

用 `schema_version: work-result/v1` 交接：`work_id`、`skill`、`outcome`、`subject`、`evidence`、`unresolved`、`changed_assumptions`、`next_action`。`subject` 至少有 `kind` 和实际 `id`；聚合视图列出被汇总的真实对象。证据记录出处、范围、状态、提供者和对象版本。

- **COMPLETE**：请求范围内的阅读视图已形成；仍可包含明确标注的未知或失败。
- **INCONCLUSIVE**：关键事实相互冲突，现有只读依据不能支持用户要的结论。
- **BLOCKED**：缺少必要读取权限或关键资料，提供已能确认的部分和具体缺口。

将 `next_action` 作为建议返回，不执行它。简报产出完成不代表项目目标完成，也不构成新的批准。

静态源码事实使用 `status: OBSERVED` 与 `kind: source_inspection`；引用旧实测使用 `HISTORICAL` 并保留其对象与日期。证据可记录 `id`、`locator`、`scope`、`status`、`producer`、`subject_id`，不把静态或历史证据标为当前实测 `PASS`。

JSON 交接时，next_action 与 evidence.scope 使用非空文本，结构化详情另放扩展字段；subject.id 使用含真实版本的不可变身份。引用不同对象的原始材料时保留原 subject_id 并标 relation=background，直接结论绑定当前对象；独立工具的原报告原样保留，由交接层包装，不要求它改用本格式。
