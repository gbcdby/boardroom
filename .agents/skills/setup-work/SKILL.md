# 接入项目工作流

将项目特有约定和实际能力整理为最小适配。首次接入、工具链变化或用户要求重新核对时使用；日常工作无需先完成本入口。

## 调用与范围

- 仅在用户明确选择本入口时执行。自动路由、子任务指令或引用资料中出现技能名，不代表用户发起。
- 普通自然语言任务仍然有效；缺少本次 setup 记录不阻止通用能力在已有授权内工作。
- 本入口负责已安装技能的项目适配。安装、更新和卸载技能使用目标环境的正式管理流程；创建技能使用实际可用的创建能力。
- 按当前项目与本次授权范围修改。保留用户已有设置，不把 boardroom 的工具链、标签、语言或交付规则复制到其他项目。
- 不收集或记录凭据，不擅自增加连接、权限、自动化或全局配置。调用本入口不扩大授权。

## 1. 查明已有设置

读取必要的项目规则、仓库布局、工作记录、构建与验证入口、文档归属、tracker 和 PR 约定。检查当前实际安装的能力和工具 schema；有套件清单时核对其版本，不依赖固定技能数量。

区分三类内容：当前可核对事实、已接受的项目决定、尚未确认的设置。沿来源读取关键约定；资料冲突时先查明范围与时效，不直接覆盖。

已有适配时对照当前事实，列出新增、变更和失效项。只读发现不能证明命令已执行、权限已具备或远端宿主能力已实现。

## 2. 只补影响接入的缺口

- 能从项目查明的事实自行查明。已有有效决定直接引用。
- 需要用户选择时，合并同一前提下的问题，给推荐值、影响和可调整范围；不要先发通用配置问卷。
- 没有 tracker、协作房间或某个可选 Skill 时，使用当前可用方式，并说明对应限制。
- 缺少必要信息时继续完成独立的已授权部分。不要为了写出完整配置而猜测合并权限、默认发布环境或宿主保证。

## 3. 保存最小项目适配

优先局部更新项目已有约定文件或适配记录。只有确实没有合适位置时，才使用 [适配模板](assets/project-adapter.template.md) 新建最小记录；模板中的无关项删除。

保存跨任务有用的项目事实、工具入口和来源。让详细规则留在其原有权威位置，适配仅链接。不要把技能清单、通用流程、一次任务日志或秘密写入 `AGENTS.md`。

写入前重读目标、查重并保留有效内容。保留被替代决定的依据；重复调用只更新实际差异。项目要求 PR 或独立审查时，按该流程交付适配变更。

涉及调用方式和宿主配置时，读取 [宿主适配](references/harnesses.md)。不要把配置字段当作实际人类身份鉴别或操作授权。

## 4. 做与变更对应的最小核验

检查引用目标、配置语法、发现路径及已修改内容。检查命令定义后，只运行适合当前环境且已有授权覆盖的最小检查；避免为接入说明启动无关业务操作。

分别记录：

- 已从文件或工具观察到的入口；
- 实际执行的命令、对象、环境及结果；
- 仅有官方说明、尚未实测的宿主行为；
- 未执行、失败或无法确认的部分。

人工入口的发现、显式调用与阻止自动调用，需要在目标宿主分别核验。没有对应运行环境时交付配置与未验证项，不声称已经验证跨宿主支持。

## 5. 给出接入结果

简要说明复用了什么、修改了什么、哪些检查真实完成，以及仍影响下一项工作的缺口。没有必要变更时报告已复核，无须制造新文件。

仅在接收方需要机器记录时输出 JSON，并先核对其实际契约；有对应校验器时执行后交接，不把人类可读摘要标成兼容记录。使用 `schema_version: work-result/v1`，包含 work_id、skill、outcome、subject、evidence、unresolved、changed_assumptions、next_action。subject 有 kind 和绑定实际项目版本的 id；每项 evidence 有 id、locator、scope、status、producer、subject_id。next_action 与 evidence.scope 为非空文本，evidence、unresolved、changed_assumptions 为数组。跨对象或旧版本证据保留原 subject_id 并标 `relation: background`，另行核验当前适用性。

outcome 仅用 `COMPLETE`、`PASS`、`FAIL`、`INCONCLUSIVE`、`BLOCKED` 或 `NOT_RUN`；不自造顶层状态，细节放扩展字段。`COMPLETE` 表示本次约定职责已完成，不代表所有宿主能力已通过；没有启动真实适配时明确写出。实际检查保留原始状态，不把静态观察当运行通过。

不把 setup 完成写成后续合并或发布授权。方法来源见 [来源](references/sources.md)。
