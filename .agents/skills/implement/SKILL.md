# Ticket 实现

## 调用方式

本技能由用户显式触发。实现完成后调用 `code-review`（模型可触发）；评审通过后可调用 `pr` 生成描述并创建 ready PR，合并由用户决定。

## 目标

把一张已确认的 ticket 实现为可运行、可测试、可评审的变更。实现不扩大范围，也不重新定义需求；测试写法由 `tdd` 负责；ticket 或 spec 有问题时，回到上游修正。

## 前置条件（硬门禁）

- ticket 已拆出并经用户确认，就绪标签为 `ready-for-agent`；`blocked_by` 中的 ticket 均已关闭。
- 来源子 spec 和主 spec 已确认（不带 `needs-info`）。
- 测试 seam 已在 ticket 或 spec 中写明；缺失时先提出 seam 并请用户确认。
- 用户已明确要求实现。拆票完成不等于开始实现。

任一条件不满足时，先补齐；不要在实现过程中自行补充需求。

## 流程

1. 读取 ticket（issue）、父/子 spec 的相关章节和验收 ID；先说出 ticket 标题和当前状态。
2. 复述本次交付的行为、范围和不包含；发现 ticket 与 spec 冲突时停止并报告，不自行裁决。
3. 确认测试 seam：优先复用已有 seam，选择尽可能高、尽可能少的公共边界。
4. 按 `tdd` 技能推进红绿循环，一个 seam 一个循环。
5. 验证：
   - 频繁运行相关测试和类型检查；
   - 完成时运行全量测试；
   - 涉及宿主能力时，记录实际命令、宿主版本和结果；未实测项明确标注。
6. 按项目约定更新 ticket：认领（assign）→ 实现完成后把就绪标签从 `ready-for-agent` 换成 `ready-for-human`，并用评论写清验证命令和结果。
7. 交给 `code-review` 并等待结论。未经用户要求，不开始下一张票、不合并、不发布；评审通过后如需提交，使用 `pr`。
8. 评审通过后关闭该 ticket（issue），不把已完成的工作留在开放状态；关闭时移除就绪标签。PR 被打回或关闭时重新打开 ticket。
9. 评审打回时，只修复与本次变更相关的问题；修复后重新验证并再次提交评审。

## 实现规则

- 不引入 spec 或 ticket 没有的新需求、抽象或配置。
- 不做与当前 ticket 无关的重构；发现必要的前置重构时，先说明并征求用户意见。
- 保持变更可回滚、可审查；小步提交。
- 不把未验证的宿主能力写成事实。
- 不修改 spec；需求有问题时回到 `to-spec` 或询问用户。

## 完成判据

- ticket 的验收项和完成定义全部满足。
- 自动化测试和全量测试通过。
- 变更范围与 ticket 一致。
- 验证记录可追溯。
- `code-review` 无阻塞问题。
- ticket 已关闭，未残留就绪标签。

## 反模式

- 拆票完就自动开工。
- 边实现边扩大范围，或顺手重构无关代码。
- 跳过 `tdd` 直接堆实现，再回头补测试。
- 没有确认测试 seam 就开始写测试。
- 把未实测的宿主行为写成已验证。
- 评审打回后绕过 `code-review` 直接合并。

## 与其他技能的关系

- `tdd`：红绿循环由它负责；本技能只决定做哪张票、做到什么范围。
- `code-review`：实现完成后调用；评审结论驱动的修复回到本技能。
- `pr`：评审通过后生成 PR 描述。
- `to-tickets`：提供 ticket、seam 和验收 ID。
- `to-spec`：需求有问题时回到上游，不在实现中改需求。
