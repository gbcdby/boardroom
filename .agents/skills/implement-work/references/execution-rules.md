# 实现执行规则

## 发现项目能力

先读项目指令、目标文件、相关调用方、已有验证入口与依赖清单，再执行匹配当前范围的命令。只选择实际存在的能力，不因语言名称猜测项目架构。

| 发现对象 | 可读线索 | 要确定的事实 |
| --- | --- | --- |
| JavaScript / TypeScript | package.json、锁文件、工作区配置 | 正确包管理器、脚本、运行时版本、前后端边界 |
| Python | pyproject.toml、锁文件、测试配置 | 环境管理器、测试入口、类型检查约定 |
| Go / Rust | go.mod、Cargo.toml、工作区配置 | 包边界、特性开关、已有测试命令 |
| JVM / .NET / 其他 | 构建文件、CI 配置、项目文档 | 实际工具链、模块、生成代码与外部服务 |
| 纯文档 / 配置 | 构建与链接检查、说明引用的源码 | 要核对的事实、示例命令、必要的渲染或语法检查 |
| 受限宿主 | 已暴露的工具及版本 | 是否可读写、执行、创建子代理、隔离工作树；缺什么 |

不要同时运行表中所有工具。只读发现优先；读取 CI 命令也不表示已在本机运行。缺少工具时优先选择现有等价能力；在已有授权和项目约定内补齐必要的项目依赖或局部工具。升级依赖、改变全局配置或扩大服务范围须符合实际任务授权；无法补齐时准确报告未运行。

## 小步实现

1. 把目标转成可观察的前置条件、动作、结果；保留验收条件的原始标识。
2. 优先在现有公共边界建立最小反馈。已有测试能精确覆盖时直接复用。
3. 为行为缺陷先构造可重复的失败；检查失败是否来自目标行为，而非依赖、语法或环境。
4. 实施一小块变更后运行相关反馈，再决定下一块。重构只在必要反馈通过后进行。
5. 修改公共 API、异步边界、数据形状或生命周期时，查找生产调用方、测试调用方、适配器与文档。文本合并成功不足以确认这些消费者兼容。
6. 不为可逆、低风险文档或样式改动新建逐字镜像测试。核对真实出处、链接、语法或渲染即可；项目硬性门禁仍适用。

不要用实现值计算期望值来制造绿灯；不要删除有效断言、跳过失败或扩大 mock 范围以掩盖问题。发现测试本身过时时，先说明契约依据，再修改它。

## 已有 TDD / 实现技能的接入

调用前读取当前技能元数据、前置条件与项目适配。使用本技能的方法和调用原技能是两件事；在结果中准确记录实际采用的路径。

| 现有约束 | 接入方式 |
| --- | --- |
| 用户专用入口、disable-model-invocation | 保留调用边界。不要读取其正文后执行同一流程来规避限制；需要时让已有授权的调用方接管。 |
| TDD 要求已确认的 test seam | 查找契约中的已确认边界及其出处；缺失时不得声称满足原技能前置条件。只有项目允许自行选择时，才使用本技能自己的测试设计。 |
| 实现总调度器要求子代理、票据 DAG | 仅在这些条件真实存在时接入；本技能本身允许单负责人完成小任务。 |
| review / PR 有独立入口 | 交付候选、检查记录与剩余问题，不借实现完成状态代替后续结论。 |

方法来源核对：boardroom 在固定版本的 [tdd](https://github.com/gbcdby/boardroom/blob/eea2f06c72eb76e300cdd4d2270facb30c6cff49/.agents/skills/tdd/SKILL.md) 要求已确认 seam；[implement-spec](https://github.com/gbcdby/boardroom/blob/eea2f06c72eb76e300cdd4d2270facb30c6cff49/.agents/skills/implement-spec/SKILL.md) 是用户入口且要求子代理。这里借鉴行为驱动的小步反馈、契约交接与调度隔离；不宣称调用了 Matt 原版，也不假设其他仓库具有这些规则。项目实际版本优先。

## 单负责人和隔离

为当前工作单元指定一名写入负责人，并记录其文件或工作树边界。其他代理可提供只读研究、验证或审查；不要让多个执行者同时修改同一工作树。

需要拆分时先形成互不冲突的工作单元与各自负责人，由上层协调集成。没有隔离条件就串行处理。不能从聊天中的“我来做”推断持久锁或租约；只使用环境真实提供的机制。

保护用户已有改动；遇到重叠改动先对比并保留意图，不自动 reset、clean、覆盖或 stash。中断恢复时重新读取当前内容和状态，不凭旧上下文继续写。

## 交接身份

- 已提交候选：记录真实提交、基线、契约版本以及构建或环境版本。
- 未提交候选：记录基线提交和完整改动清单，包括 staged、unstaged、untracked 及删除；以真实内容摘要或可重建快照标识候选。
- 不把 HEAD 单独当作脏工作树的身份；不要编造摘要。无法固定并发变化时声明身份不稳定，不能转交为可复用验证证据。
- 只记录与验证有关且可安全公开的环境信息；不要收集完整环境变量或凭据。
