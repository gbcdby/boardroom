# 按契约实现变更

把当前工作做成可检查、可交接的实际候选。遵循用户已有授权与项目约定，只在影响目标或权限的实质缺口处升级问题。

## 1. 恢复输入与当前状态

- 读取项目指令、当前目标、验收条件、相关设计和已有决策；优先使用当前有效版本。
- 沿用 work_id；没有时创建本地工作标识。明确本次范围与唯一写入负责人。
- 检查目标文件、相关调用方、工作树现状和用户已有改动；不要用旧上下文推断现状。
- 记录实际基线、契约版本、已知失败和环境限制。可用提交、文件快照或等价产物，不强制 Git。
- 简单修正可使用一句目标与验收条件；不要为了进入流程先制造完整规格书。
- 对可逆且已有授权的实现选择自行判断并记录假设；需求矛盾或关键设计未知时先完成不受影响的工作，再提出最小问题。

## 2. 发现能力与边界

- 检查实际清单、锁文件、构建配置、测试与 CI 入口，确认语言、运行时、包管理器和工作目录。
- 阅读 [执行规则](references/execution-rules.md) 选择当前项目可用的实现与反馈方式。
- 优先项目已有工具；在已有授权和项目约定内补齐必要的项目依赖或局部工具。不要为了获得绿灯擅自升级依赖、扩大全局配置或绕过环境限制。
- 有现成实现或 TDD 技能时核对其入口、test seam 和调用前置条件；不要仅凭技能名称判断兼容。
- 保留用户专用调用边界；不得靠读取受限技能正文来绕过 invocation 限制。
- 原技能要求已确认 test seam 时，记录真实确认出处；本技能不替它补造确认。
- 不依赖特定语言、MCP、票据系统或其他技能；缺少工具时用已有等价能力或准确记录阻塞。

## 3. 选择最小实现片段

- 把目标拆成能够观察结果的小片段，每片关联验收条件与受影响边界。
- 优先复用既有抽象和测试入口；仅为解决当前问题引入必要的新边界。
- 行为缺陷先建立可重复反馈；文档改动先列待核对的事实与出处。
- 检查公共 API、异步返回值、数据形状、持久化和生命周期变化涉及的所有消费者。
- 涉及架构约束或协议性质时使用现有设计交接；设计不足则反馈具体缺口，不替形式化结果作源码保证。
- 只为当前单元指定一个写入负责人；并行助手可研究或审查，不能竞争修改同一工作树。

## 4. 实现并获得小步反馈

1. 选择一项可观察行为或事实，并确定验证入口与独立期望。
2. 对行为缺陷运行最小复现，确认失败来自目标问题；环境错误不能冒充红灯。
3. 完成足以满足该片段的变更，保留用户已有改动与无关文件。
4. 运行相关检查，保存原始命令、状态与日志；检查失败原因后再决定下一步。
5. 在反馈通过后做必要重构，再进入下一个片段。

不要批量写完所有测试再批量写实现，也不要把实现值复制为测试期望。
不要通过删断言、跳过有效失败或改变需求来制造通过。
可逆的低风险文档、格式和样式修正不必新建逐字镜像测试；采用适合其风险的事实、链接、语法或渲染检查。
遇到既有失败，先确认是否由本次改动引入；保留比较证据，不顺带修复无关范围。

## 5. 固定交接候选

- 汇总完整实际改动，包括 staged、unstaged、untracked、新增与删除；防止只看提交遗漏工作树内容。
- 记录 subject.kind 与真实 subject.id；按需补 base_id、contract_id、environment_id、worktree_digest。
- 未提交工作以真实内容摘要或可重建快照识别；不要仅用 HEAD 标识脏工作树，不编造摘要。
- 检查证据对应的候选是否仍然一致；检查之后又修改内容时，重新检查受影响范围并更新证据。
- 若共享工作树持续变化，先取得稳定候选；无法稳定时返回 INCONCLUSIVE，不转交虚假的固定身份。
- 把作者检查与独立验证分开，注明未覆盖范围。更多代理或模型不等于更强证据。

## 6. 返回结果并交接

使用 [实现结果模板](assets/implementation-result.md)，或返回具有同等字段的简洁文本。
保持共同结果约定 `work-result/v1`：schema_version、work_id、skill、outcome、subject、evidence、unresolved、changed_assumptions、next_action。
证据至少可追溯到原始出处、覆盖范围、原始状态、执行者与实际候选；保留相关工具版本。

| Outcome | 使用条件 |
| --- | --- |
| COMPLETE | 当前实现产物已完成，实际完成的检查及缺口已记录；不表示整项交付完成。 |
| FAIL | 已确认当前实现不满足明确的验收条件，且本轮未修复。 |
| INCONCLUSIVE | 已开展工作，但候选、环境或关键依据不足，不能确认完成情况。 |
| BLOCKED | 缺少必需输入、能力或权限，无法继续当前实现。 |
| NOT_RUN | 尚未进行本次实现。 |

本实现环节必需检查失败或未运行时不得返回 COMPLETE；按已确认违约或证据不足返回对应状态。
可在 COMPLETE 中注明由后续独立环节执行的检查，但不得写成已经通过。
本技能不授予推送、创建 PR、合并或发布权限；已有授权由后续职责继续使用。
无需替用户重复确认已有授权，也不要自动调用受限的总调度技能。

## 最小返回示例

```yaml
schema_version: work-result/v1
work_id: DOC-17
skill: implement-work
outcome: COMPLETE
subject:
  kind: artifact
  id: README.md@actual-snapshot-id
  base_id: actual-base-id
  contract_id: DOC-17/accepted-scope-v1
evidence:
  - id: E-1
    locator: actual-source-path@actual-revision
    kind: source_inspection
    scope: README 中的当前功能说明
    status: OBSERVED
    producer: author-session
    subject_id: README.md@actual-snapshot-id
unresolved: [尚未独立审查，未进行运行时验证]
changed_assumptions: []
next_action: 将候选及事实出处交给审查负责人
```

示例标识是占位值；实际执行必须换成真实值。静态事实核对不能写成运行时测试通过。

JSON 交接时，next_action 与 evidence.scope 使用非空文本，结构化详情另放扩展字段；subject.id 使用含真实版本的不可变身份。引用不同对象的原始材料时保留原 subject_id 并标 relation=background，直接结论绑定当前对象；独立工具的原报告原样保留，由交接层包装，不要求它改用本格式。
