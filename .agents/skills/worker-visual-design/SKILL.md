# 美术方向与界面规格

将参考和真实任务转成可执行的视觉规则与界面合同。具体风格、参考作品、已定图像和组件取值归项目资料；本技能只维护通用方法。可跨项目、跨语言独立使用；按任务选择方法，不要求安装其他技能或建立整套资料目录。

## 工作流程

1. **固定范围与依据**：读取项目指令、共享 Spec 的有效修订、相关规范、页面合同、组件索引与实际实现、token 和当前设计基准。记录本次继承的公共修订；向上核对页面壳、导航和全局层，向下核对组件与素材依赖。区分现状、已采用设计与本轮提案，沿用已有确认和授权；冲突按具体字段与采纳范围处理，不按文件新旧整份覆盖。关键引用缺失时先找项目现有入口，明确缺口，不靠空模板或自行猜测代替有效规范。产品行为或状态归属存在缺口时交给 `worker-design`。
2. **查看参考**：分别标明画风参考、布局基准和实现现状；先看总览，再检查影响判断的原图局部。重要结论关联可定位的来源；需要长期登记或固定基准时记录编号、版本／哈希。将可见事实、跨图规律、推断与用户决定分开。
3. **形成设计**：整体方向说明形体、笔触、色光、材质、细节、空间和留白的关系，保留允许分支与排除项。界面先发现已有组件，按“直接复用 → 既有变体 → 必要组合／扩展 → 有依据新建”设计；重复且稳定的模式按复用价值形成组件合同与抽取范围，交接实际实现，不把设计条目标成可用代码。已有界面与跨页任务先按[公共基准](references/component-system.md#4-继承公共基准)固定必须继承的外观和允许变化项；原组件、原素材与 token 进入实际产物，出图输入同样受约束。局部偏好不升级为全项目默认。
4. **解决不确定性**：选择能区分方案的最小对照、图片或隔离原型；按实际显示尺寸、整体与相关局部自查。多页、公共组件或整体风格任务增加同条件页面与同用途控件的横向比较，逐项对照公共基准与实际产物，区分授权变体和无依据分叉，不能仅凭逐页好看或简报写了“遵循规范”判定统一；小改动只查受影响关系。记录实际对象与证据，分开说明设计自查、运行观察及未测范围。
5. **归档并同步**：在已有写入授权内，把已确认或按有效授权采用的设计原图／稳定版本归档到项目文档与资产体系，维护当前有效入口、采纳范围与历史替代关系。设计修订时同批同步图像、相关规范、页面合同、组件入口及验收依据；实现与复验未完成则保留待同步状态。按[设计归档](references/design-archive.md)执行，不用实现截图替换设计基准。
6. **交接结果**：交回本次复用、扩展、新建及迁移范围、公共基准修订、档案位置、受影响页面与未同步项，沿用项目现有任务记录。只读请求只交回发现与建议；agent 提案不写成用户决定，不为已有授权内的记录重复问人，无新结论不制造日志或第二套任务板。

## 可选能力与职责交接

- 先核实能力可用、适用及调用限制，再使用 `prototype`、`huaban-ui-ref`、图片或 Rive 工具；不通过读取正文绕过人工专用入口。无需这些工具也可交付设计简报与规格。选图、原型的顺序和停点以用户要求与项目合同为准。
- 参考搜集只提供候选；长期入库按任务授权执行，入库不等于风格采纳。图片预览与正式素材分别保存；使用图片工具时只输出必要元数据，不打印 base64。
- 据已确认设计图落实界面时，按名称交给 `worker-ui-fidelity`；通用实现与 TDD 交给 `worker-implement`，独立检查交给 `worker-verify`／`worker-review`。本技能可自查设计或隔离原型，不代替这些角色，也不接管后续调度、PR 或发布。
- 捆绑 CLI 是可选资料工具：`art_direction.py init` 会补建模板，`ingest` 会复制图片并登记，`check` 只查完整性；`color_check.py` 只计算声明的纯色色对。具体用法见维护参考，不默认运行初始化。

交回 Spec／页面合同与设计档案的位置及修订、采纳范围、组件和素材入口、自查证据、未决项与后续验证输入。完成仅表示本次设计范围已交付；图片归档或规范更新不代表组件实现、页面迁移或运行验收已经完成。
