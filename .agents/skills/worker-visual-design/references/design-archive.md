# 设计图归档与改版同步

在已有写入授权内，把用户确认或按有效授权采用的设计图归档为项目可持续读取的基准，并在本次工作中同步相关合同。沿用已有决定，不为保存已采用设计重复询问；候选、参考的长期保存仍按任务范围处理。

## 区分资料身份

| 资料 | 用途与边界 |
|---|---|
| 参考图 | 提供画法、布局或配色依据；借用范围不等于整图采纳 |
| 设计候选 | 供比较和选择；未采用时不能作为实现或验收基准 |
| 已采用基准 | 记录确认或授权依据、适用范围与版本，供设计、实现和验收共同引用 |
| 实现截图 | 记录实际运行结果及其候选、环境和状态，不替代设计基准 |

生成图保留原始版本与生成来源；标注、裁切和组合另存派生版本。采用组合时逐区域关联来源，例如标题来自 A、主体来自 B，不把整张 A 或 B 写成全部采用。概念图中的文字、数量与交互仍按页面合同核对，不能将生成图称为真实运行效果。

## 保存位置与最小记录

优先使用项目现有文档、资产目录或能可靠回读指定版本的设计工具。保存持久原文件，或保存稳定的文件／画板与版本标识；会变化的“最新图”链接、对话图片和临时下载地址不能成为唯一依据。通过实际读取确认入口可用。没有合适结构时，可在 `docs/design-direction/` 下只补所需设计文件与一份入口索引，不强制初始化整套模板或另设编号体系。

在现有页面合同、组件目录或设计记录中按适用范围保留：

| 信息 | 记录内容 |
|---|---|
| 对象与显示条件 | 页面／组件、状态、平台、视口或画幅；未知项明确标注，不能猜作已确认 |
| 图像身份 | 实际路径或版本化设计链接、修订、来源；本地文件的内容哈希或工具稳定版本标识 |
| 采纳依据 | 采纳范围、决定者或有效授权依据、日期；区分用户确认与授权内的 agent 选择 |
| 当前入口与历史 | 当前有效版本、所替代版本、相关页面合同／公共规范／组件／验收入口 |

沿用项目已有标识和记录格式。缺少原图或访问能力时注明缺口，继续不依赖图片的规格工作；不得重新生成一张图冒充原确认图，也不能把归档未完成报为完成。

## 改版时同步受影响项

1. **先核对当前版本。** 读取最新有效图、合同和组件记录，确认本轮采用依据与变更范围。并行任务已更新时合并仍有效的决定；冲突写明对象与差异，按项目既有决定路径处理，不以覆盖文件解决冲突。
2. **保存新旧关系。** 新图另存可定位版本，记录变化及替代范围；更新当前入口，保留项目正常历史。局部替换不废除未受影响的区域和规则。
3. **在同一工作批次同步设计记录。** 逐项更新下表中受影响内容；无变化的项保留原引用，不复制整套规范。

| 受影响内容 | 同步要求 |
|---|---|
| 设计图与页面合同 | 图像版本、布局、状态、素材、局部例外与采纳范围一致 |
| 公共规范与 token 目标 | 更新共性与变体规则，链接真实实现入口，区分已实现值与设计目标 |
| 组件目录与消费者 | 记录组件／变体变化、复用入口及受影响页面；不能只更新当前一页 |
| 验收基准与变更影响 | 指向有效设计修订，说明需重验的状态与页面、现有证据是否仍适用 |

设计同步不等于修改业务代码或完成验收。实现尚未跟进时分别标明“设计已更新／实现待同步／待验证”，并交回受影响入口；不能把旧实现或旧截图标为满足新设计。基准变化必须有有效设计决定和替代记录，不得为消除实现差异悄悄换图、放宽要求或用运行截图覆盖基准。

## 交付前核对

- 从项目既有入口能打开当前有效图及必要历史，图像身份与记录一致。
- 页面、公共规则、组件与验收引用指向适用版本，局部采纳没有扩大为全局规则。
- 受影响消费者与待同步项可定位，未覆盖并行工作中的有效决定。
- 分别报告归档、设计更新、实现同步和验证的实际状态；规范更新不启动后台监视或定期任务。
