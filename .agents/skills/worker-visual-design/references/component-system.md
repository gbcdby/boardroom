# 组件发现、抽取与跨页一致性

沿用项目的组件索引、公共规范和代码入口，只处理本次涉及的组件及消费者。小修复用已有条目并检查关联影响，不要求全量盘点、另建组件库或补齐无关状态。

## 1. 先发现，再选择

设计前按用途和语义检索项目组件索引、有效设计合同及实际代码，查看候选的实现、变体、状态和使用位置。区分已采用设计、当前实现与废弃候选；索引声明不能代替代码核实，偶然页面样式不自动成为公共规范。

从页面向上追查公共壳、导航、全局浮层和反馈投影，向下查所用字体、图标、素材及状态来源；只读页面内部会漏掉实际可见的公共对象。同一数据在局部入口、全局导航等多处显示时，一起核对本次状态。区分可见项、可操作项与路由数量，不能凭一份旧清单删去现存能力。

合同与实现不同时分字段处理：有效采纳决定约束目标，代码说明当前能力和状态；查明替代范围后保留未被取消的内容。没有依据时记录冲突与待定部分，不把“代码较新”或“页面更具体”作为整体覆盖理由。

按“直接复用 → 已有变体 → 必要组合／扩展 → 有理由新建”选择。优先用现有组件组合解决页面需求；不能复用时说明真实内容、职责、状态、平台或可访问性上的缺口，以及本次新增范围。已有确认图但无实现时继承其适用视觉规格，并保留待实现状态。

## 2. 按复用价值抽取

模式已在多处使用或已有明确的多处复用需求，且语义、职责、结构与状态逻辑稳定时，抽取可共享部分，减少重复维护和无理由分叉。不按机械出现次数决定，也不因外观相似合并不同操作语义。

先明确基础元素、组合组件与页面组合的关系，再选择变体、参数或插槽表达稳定差异。不要将一次性装饰或尚不明确的差异塞进万能组件；需要大量互斥开关时重新检查职责边界。产品行为或状态归属不清时交回 `worker-design`，不借组件设计新增业务能力。

## 3. 维护最小组件合同

在既有索引或公共合同补充相关条目，引用真源，不复制整套 token 或另建平行规范。至少说明下列内容；不适用项写明原因，已有内容直接引用。

| 内容 | 需要固定的关系 |
|---|---|
| 用途与边界 | 名称、语义、职责、适用平台／页面，以及不适用情境 |
| 组成层级 | 构成元素、容器和内容关系，依赖的子组件、可组合部分与插槽 |
| 状态 | 适用状态、视觉变化及已有行为约束；未知状态不伪装为默认 |
| token 与变体 | 字体、颜色、间距、形状、素材和动效的引用，必须继承的外观、允许的变体与变化边界 |
| 内容与适配 | 固定／最小／伸缩尺寸、平台单位、长文案、大字号、溢出和命中区等相关约束 |
| 依据与实现 | 设计基准及修订、实际组件／素材入口、已使用页面与明确预期消费者 |
| 迁移与例外 | 替代对象、受影响页面、迁移范围、局部例外的原因与来源，以及当前完成状态 |

分别标明设计已采用、待实现、已实现和已验证的范围。没有实现的组件不得标为可用（available）；已有代码也不等于运行验收通过。索引缺项只补本次需要的入口。

## 4. 继承公共基准

先复用项目已有公共规格与可见样本。对本次会出现的共同对象，在现有简报或合同中记录一份最小基准：**来源／修订 → 必须继承的外观与状态 → 允许变化项及适用范围 → 产物中的使用位置**。已有信息直接引用；精确值以原 token／实现为准，不另维护色板或组件库。缺项只补本次所需，未采纳项保持提案状态。

交接优先完整引用原组件合同，避免重抄成第二份配方。确需列出精确值时，按各组件的作用范围、默认值、继承和局部覆盖逐属性核对；同名、同字号或外观相近，不代表行高、字重、间距等属性也共用。未显式声明的属性先查其生效来源，不用相邻组件的显式值补齐；无法确定时保留缺口，不凑成统一值表。

- **共同视觉语言**：从有效参考和组件样本确定字体层级、色彩职责、边缘与材质、图标造型、细节密度及留白关系。只有“简洁”“水墨”等风格词不足以让独立作者复现；缺少原图或字体、纹理时说明哪些视觉关系尚不能核实。
- **组件不变量**：明确同用途控件的结构、字体、形状、素材、状态语言和既定尺寸关系。尺寸仍区分固定、最小与伸缩；不能为了贴图把命中区或可适配尺寸锁死。
- **允许变化**：沿用组件已有参数、状态与明确采纳的局部变体；页面可调整合同允许的布局、内容、场景与色彩分支。统一公共规则，同时保留页面身份；不把局部例外推广全局，也不为统一外观取消有效例外。

在可运行的样本与实现交接中，优先直接使用原组件、原 token 与原素材；不要在消费页重新写一套近似样式或私自覆盖公共 CSS／属性。只有名称相同、颜色接近或图形相似，不构成直接复用。无法使用原件时明确替代范围与原因，保留待核对状态。

图片输入同样引用这一基准，分别说明原样保留的公共部分、允许选择的变体和待探索部分。优先让现有组件与素材承接已固定的界面，把生成自由度留给本次未确定的画面；需要工具近似重绘时，必须标明并在产物中逐项检查，不能凭提示词宣称复用成功。生成图偶然出现的样式不成为新规范。

并行作者使用同一有效公共基准及修订、同一批适用参考和原组件；各页只补本地差异。遇到基准冲突或重复扩展，回到项目现有规范入口明确复用、合并或有界例外，再更新受影响合同，不另设调度或审批流程。按 [项目学习](project-learning.md)同步有效决定与替代关系。

## 5. 跨页对照与交接

多页面或公共组件改动时，对受影响页面提供可比条件下的总览和同用途控件对比，说明平台、视口、字号、主题及代表内容／状态。统一条件比较共性，保留页面身份和合理差异；分别检查字体、形状、间距、图标、材质与状态语言，不以每页单独好看代替跨页一致。

实际查看整体与共享部位的局部，不只读作者自述。按基准逐项记录“来源要求 → 产物位置／实际用法 → 相同、授权变体、无依据分叉或未验证”；核查交接简报、组件映射、出图输入和实际样本之间是否互相矛盾。缺失共同对象、替换原素材、越界变体及被抹掉的合理差异都需要明确处理；文档齐全不能抵消这些偏差。

设计自查可使用设计图或组件样本，并标明其性质；真实运行截图、交互和连续动效验收交给 `worker-ui-fidelity` 或指定执行者。不能用设计对照证明实现一致，未检查的消费者保留待验证状态。

交接本次复用／扩展／新建的理由和入口，以及组件抽取、旧用法迁移的执行范围、相关页面、例外和验收输入。代码抽取与迁移交给 `worker-implement` 或既定实现角色；本技能不接管生产实现，也不将设计交付标为组件已落地。
