# 设置、审计与恢复操作

状态：已确认（实现与使用说明；最终候选验收另记）
日期：2026-11-11
来源：[阶段 5 Spec #109](https://github.com/gbcdby/boardroom/issues/109)。本文把设置与审计的操作边界放在一起；有效配置字段详见[设置文档](settings.md)，完整生命周期详见[成员与审计恢复](t3-member-lifecycle.md)。

## 1. 选择正确入口

| 想做的事 | 页面 | 操作结果 |
| --- | --- | --- |
| 查看当前服务端口、MCP 地址、存储、心跳、防环与记忆配置 | `/settings` | 读取当前进程启动时解析的白名单快照；全局页面，不随项目切换。 |
| 改下次启动使用的配置 | 配置文件或服务启动环境 | 正常停止并重启后生效，再在设置页核对；页面没有保存或重启按钮。 |
| 改项目默认 reviewer | `/projects/:projectId/tasks` | 按当前修订保存项目设置；不是全局服务配置。 |
| 配置/控制托管 Agent | `/runtimes` | 保存、应用和运行状态各自独立，真实 CLI profile 门槛仍有效。 |
| 查看成员/岗位变更、撤销或重做 | `/projects/:projectId/audit` | 以当前项目和当前事实执行完整补偿，新增审计，不抹掉原记录。 |

设置页不展示 PG 连接串、凭据、原始 argv、环境全集或任意文件内容。允许显示的路径仅为已解析数据目录与配置文件路径。刷新失败保留上次成功值及时间，并提示尚未重新确认；复制被浏览器拒绝时保留地址供手动复制，不显示假成功。

## 2. 更改配置后核对生效

1. 查看 `/settings` 的当前值、启动时间、配置文件路径与优先级规则。
2. 修改对应配置文件或启动环境。优先级为默认值 → 配置文件 → 环境变量；仍被环境覆盖的字段不会因改文件而变化。
3. 正常停止服务，使用相同存储配置重新启动；`npm start` 会先构建页面。更换数据库需另做迁移和校验。
4. 刷新设置页，核对启动时间、实际端口和 MCP 地址。必要时用 health 检查数据库探针，再执行实际业务读写。

页面刷新只是重新取服务端快照，不检查磁盘是否出现未加载修改，也不触发热加载。`storage.postgresConfigured` 只表示存在连接配置，不表示正在使用 PG 或数据库连通性已经通过。生产启动/重启证据以 [V1 索引](v1-acceptance.md)关联的实际候选结果为准。

## 3. 看懂一条审计

审计保留操作主体、时间、目标、前后值及补偿链。当前可撤销的成员/组织事件保存完整有版本快照；“查看”可以打开仍存在目标的项目页面。目标已移除或永久删除时，历史保持可读，不能以一个失效深链冒充目标仍存在。

撤销与重做都是新的有权限操作：服务端重新检查项目、成员代际、参与关系、岗位与关联任务等事实是否仍匹配。成功后新增补偿记录，原审计保留；失败显示原因，不部分修改业务，也不把按钮点击本身算成功。

| 审计结果 / 原因 | 含义与下一步 |
| --- | --- |
| 可撤销，当前事实匹配 | 人可执行撤销；完成后读回当前业务状态与新审计。 |
| 可重做 | 重做仍需匹配当前快照，不能恢复后续已经变化的关系。 |
| `compensation_conflict` | 目标事实后来变了。先检查后续记录，再决定新的正向操作；不自动覆盖。 |
| `legacy_incomplete_snapshot` | 旧事件缺少可靠恢复所需的完整关系或代际。保留历史，拒绝猜测恢复。 |
| `audit_capture_budget_exceeded` | 无法在有界预算内完整采集/执行。整笔不提交或真实回滚；缩小操作范围并检查原因。 |
| `runtime_must_stop_first` | 关联托管进程尚未确认停止。先正常停止并确认退出，过期 lease 不能当退出证明。 |

角色/状态等旧简单记录只在兼容校验足够时恢复；旧删除事件不能因为界面能显示 JSON 就被当成完整补偿。当前审计保存与用户可恢复边界见[生命周期说明](t3-member-lifecycle.md#3-审计撤销重做与安全冲突)。

## 4. 移除、恢复与永久删除的区别

暂停保留岗位和关系；移除使当前成员周期失效，保留作者与历史。移除后普通 MCP join 不能自动重新入项目。人或有范围权限的管理者必须明确重新添加同一个 Agent，平台复用保留 Member 身份并推进加入代际；重新添加不默认恢复旧群组和岗位。

审计撤销移除只恢复仍可安全恢复的关系，并推进新的代际和修订；不会回拨任务版本，也不会让旧 MCP 会话、review round、托管绑定或总结 attempt 重新运行。需要重新接入/评审/配置/总结时按实际 `restartRequired` 提示操作。

永久删除项目或群组只有人可在二次确认后执行，不能撤销。删群保留项目任务与文档，但清理该群聊天、参与关系、关联消息、来源请求/通知等；删项目清理其任务、评论和项目记忆，保留其他项目及 Agent global。实际影响看服务端当次预览，完整范围见[删除说明](t3-member-lifecycle.md#4-归档永久删除与资料保留)。
