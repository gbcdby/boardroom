# 设置与配置生效

状态：已确认  
日期：2026-11-11

从侧栏「设置」进入 `/settings`，可以查看本地服务当前已经生效的配置。设置属于整个服务，不随项目切换；没有项目时也可以查看。页面为只读，不保存配置文件，也不执行重启。

## 页面显示什么

| 区域 | 内容与含义 |
| --- | --- |
| 服务与接入 | 实际监听的地址和端口、HTTP、WebSocket、MCP HTTP 地址；可以复制 MCP 地址、打开健康检查或进入托管 Agent 页面。 |
| 数据存储 | 当前数据库类型、本地数据目录、PostgreSQL 连接信息是否已配置。已配置不表示当前正在使用 PostgreSQL，也不表示已完成数据库连通性验证。 |
| 连接心跳 | 心跳间隔和超时，同时显示便于阅读的时长与准确的毫秒值。 |
| 防环与唤醒 | 每群连续自动回复上限，以及每位成员每分钟的唤醒上限。 |
| 记忆 | 消息总结阈值、单份文档上限、单次注入上限、总结输入上限和总结执行超时。阈值用于安排请求，请求建立不代表模型已完成总结。 |
| 来源与生效 | 本次加载的配置文件路径、服务启动时间、配置优先级与重新生效的方法。 |

地址来自服务实际监听结果，不根据浏览器传来的 Host 生成。在 Vite 开发页面中读取时，MCP 地址仍指向后端监听端口。接入方式见 [MCP 接入指南](getting-started-mcp.md)；托管 CLI 的配置与控制仍在 `/runtimes`，项目默认 reviewer 仍在项目任务页。

数据目录和配置文件路径按已解析路径显示，页面不读取或展示文件内容。使用 PostgreSQL 时，本地数据目录不代表 PostgreSQL 服务端的数据文件位置。连接串、用户名、密码、token、CLI 凭据、原始启动参数、环境变量全集和其它内部路径不会出现在设置响应中。

## 修改后怎样生效

配置优先级由低到高为：**默认值 → 配置文件 → 环境变量**。环境变量覆盖配置文件中的同名设置；因此只修改文件时，仍被环境变量覆盖的字段不会改变。

1. 按 [配置示例](../config.example.json) 修改配置文件，或调整启动时使用的环境变量。`AGENT_STUDIO_CONFIG` 指定配置文件；未指定时读取启动目录中的 `config.json`。
2. 正常停止本地服务。
3. 使用原来的数据配置重新启动。例如使用同一个绝对数据目录启动 SQLite 服务，可以继续读取原有业务数据。
4. 打开设置页并选择「刷新配置」，核对值与服务启动时间；必要时打开健康检查。

服务在启动时解析配置，设置 API 返回这个进程的启动快照。编辑磁盘上的配置文件后，旧进程仍返回旧值；页面也不会检查是否存在尚未加载的文件改动。「刷新配置」只重新读取正在运行的服务，不触发热加载。

「未加载配置文件」表示这个进程没有加载配置文件，此时默认值和启动环境变量仍可生效。页面给出优先级规则及文件路径，不逐字段推断某个值来自哪一个来源。

**切换数据库须先完成数据迁移与校验。** 改配置并重启不会把 SQLite 数据自动搬到 PostgreSQL，也不会自动执行反向迁移。沿用现有[数据迁移工具](../scripts/migrate-data.ts)及其目标库检查流程。

## 刷新与复制反馈

页面记录「上次成功读取」时间。刷新失败时保留上次成功值和原时间，并明确提示这些值未重新确认；选择「重新读取」可再次尝试。首次读取失败时不填入默认配置冒充真实结果。

「复制地址」成功后显示确认信息。浏览器拒绝剪贴板访问或未提供剪贴板能力时，页面保留 MCP 地址并提示手动复制，不显示成功。所有路径与配置文字均以普通文本呈现。

## 接口与边界

`GET /api/settings` 返回 `{ settings: EffectiveSettings }`；`HEAD /api/settings` 返回对应状态及响应头，没有正文。响应使用 JSON 和 `Cache-Control: no-store`。设置页不会注册配置写入接口，也不会注册 MCP 设置读取工具。

接口沿用本地单用户产品边界，仅可信解析出的全局 human owner 可以读取。Host 必须是 `127.0.0.1` 或 `localhost`，端口必须合法；存在 Origin 时要求与请求 Host 的 HTTP origin 一致，`Origin: null` 和浏览器跨站请求会被拒绝。接口不开放 CORS。POST、PUT、PATCH、DELETE 等方法返回 405，客户端不能通过正文或请求头自报 owner 身份。

记忆页继续使用 `GET /api/memory-settings`；其中五项配置与设置页保持一致。公开字段定义见 [Settings DTO](../src/shared/settings.ts)，有效默认值和范围以[配置解析](../src/server/config.ts)为准。

## 验证入口

- `tests/settings.test.ts`：真实配置解析与字段白名单。
- `tests/settings-http.test.ts`：真实 HTTP 的方法、Host、Origin、主体与错误信息边界。
- `tests/settings-server.test.ts`：生产服务实际端口、配置覆盖、读取无写入、记忆配置一致性、正常重启生效及数据保留。
- `tests/settings-ui.test.ts`：真实 Vue SFC 的只读展示、刷新、错误与复制反馈。
- `scripts/e2e-settings-web.py`：生产 HTTP 服务与真实 Chromium 的布局、键盘、剪贴板、失败恢复和重启后展示；先运行 `npm run build`。

这些入口分别提供对应范围的证据；组件测试和构建成功不代表真实浏览器已通过，设置页检查也不证明 CLI 或模型执行能力。
